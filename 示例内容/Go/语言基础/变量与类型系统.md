# 变量与类型系统

## 学习目标

学完这一节，你应该能够：

1. 说出 Go 的零值设计与 Python/Java 默认值策略的区别
2. 正确使用 `:=` 与显式类型声明，解释编译器为何强制"声明未使用即报错"
3. 预判切片、map 在值传递下的共享行为

## 课文

### 零值：没有初始化陷阱的语言

Go 的设计哲学之一是**消除不确定性**。任何变量声明后立即有一个确定的"零值"：数值类型为 `0`，字符串为 `""`，布尔为 `false`，指针、切片、map、channel、接口为 `nil`。

对比 Java——成员变量有默认值而局部变量没有，忘了初始化就是一个编译错误（甚至运行期 NPE）。Go 把这个心智模型统一了：**你永远知道变量此刻是什么值**。

```go
var count int        // 0
var name string      // ""
var active bool      // false
var p *int           // nil
fmt.Println(count, name, active, p)
```

### 短声明 :=

函数内部最常用的声明方式。它有一个硬性约束：**:= 左侧至少要有一个新变量**，否则编译器直接报错——这是 Go "不许写死代码"严格风格的体现。

```go
x := 10          // 合法
x := 20          // 编译错误：no new variables on left side of :=
x, err := f()    // 合法：err 是新变量，x 只是被重新赋值
```

### 类型转换必须显式

Go 不做隐式转换。`var f float64 = intVar` 编译不过，必须写 `float64(intVar)`。这一条规则消灭了一整类"精度静默丢失"的 bug，代价是代码里多几个转换函数调用。

## 易错与陷阱

- **int 的大小随平台变化**（32 位机器上是 32 位）。需要确定宽度的场景（协议、序列化）用 `int32` / `int64`。
- `:=` 在 if/for 初始化语句中会**遮蔽**（shadow）外层同名变量——出了作用域外层变量纹丝不动，是常见 bug 源。
- string 底层是字节切片，`for i := 0; i < len(s); i++` 按**字节**遍历，中文多字节字符会被切碎；要按字符（rune）遍历用 `for range s`。

## 小结与自检

- 零值设计：任何变量都有确定初值
- `:=` 至少引入一个新变量；类型转换必须显式
- int 宽度不确定 → 跨平台用定宽类型；中文遍历用 `for range`
